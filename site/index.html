AILet Claude set up and check your backups

Open source · Backup & restore for MySQL, MariaDB, PostgreSQL and SQL Server

Backups that never lock the database. Recovery to the exact second.

DumpCat is a single binary with a web UI. It schedules backups, compresses and encrypts them, ships copies to S3, Google Drive, OneDrive or SFTP, verifies them and brings your data back when you need it. Runs on Linux and Windows, fully offline.

Install

Running in a minute

One command on Linux, download and double-click on Windows. The installer sets up a service that starts with the machine and the backup tools that match your database version; the web UI is built into a single file.

On the Linux server, paste this command and press Enter:

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

It downloads the latest release, checks its checksum and installs it to /opt/dumpcat as a systemd service, with rclone, the MySQL/MariaDB client, the matching mariabackup or XtraBackup, and mydumper when the repositories have it; --postgres 16 adds the PostgreSQL 16 client tools. Options go after sh -s --: --port 9090, --listen 127.0.0.1, --tls-auto.

  1. Download the .zip Download for Windows 1.8.0
  2. Unzip it: right-click the file, choose Extract All.
  3. Double-click Install DumpCat and answer Yes. Your browser opens DumpCat; the install window shows the setup token.

Windows 10 / 11 or Windows Server 2016+ 64-bit, runs as a Windows service. Prefer PowerShell? Run irm https://dumpcat.cc/install.ps1 | iex in PowerShell (Administrator). mydumper and XtraBackup for MySQL are not available; run DumpCat on Linux for databases of hundreds of GB.

New to the command line? Follow the step-by-step guide, with fixes for common problems.

AI-friendly · MCP

Let an AI assistant set up and watch your backups, without handing over the keys

DumpCat is an MCP server. Connect Claude Code, Claude Desktop or any other MCP client with an API token and ask in plain words: the assistant adds servers and storages, creates jobs and restore drills, finds what failed or is overdue, reads the log and tells you why. Passwords and keys you enter yourself, in the web UI. Other AI agents read the API reference in Markdown that your own server writes for them.

What an assistant may do

  • LookRead-only token, the defaultOverview and alerts, jobs, backups, errors and logs, binlog / WAL archiving, restore and drill results, point-in-time recovery previews.
  • StartFull-access token, operator or adminRun a backup, verify a backup, start a restore drill. The AI client asks you before each one.
  • Set upManage tokenAdd servers and storages, create and change jobs and restore drills. Passwords, keys and passphrases never pass through the assistant: it gives you a link to enter them yourself.
  • Never over MCPWith any tokenRestores, deletions and DumpCat’s settings. No option turns them on: these stay in the web UI.

Answers never contain passwords, keys or tokens, and no tool takes one; credentials that turn up in errors and logs are masked. Every call goes through the REST API with your token, so it is checked like any other request and written to the audit log.

Connect in a minute

  1. Create a tokenThe API & MCP page in DumpCat, New token: Read-only (the default) looks, Full also runs backups, Manage also sets them up.
  2. Copy the setupThe page fills your server’s address and the token into the Claude Code command, the Claude Desktop config and the setup for other clients.
  3. Test, then askTest MCP connection shows the account, the access and the tools the assistant will get.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

Put in your own address and token, or copy the filled-in command from the API & MCP page. To share the server in a project without the token, that page also has a .mcp.json that reads the token from your environment.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Open Settings → Developer → Edit Config, paste, and restart Claude Desktop. dumpcat mcp is a small stdio bridge that runs on the computer with Claude Desktop; on Linux, command is the path of the dumpcat binary, and on macOS you build it with Go.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }
  }
}

The /api/mcp endpoint (streamable HTTP) is part of DumpCat, nothing else to install. Clients that only start a local command use dumpcat mcp, with DUMPCAT_MCP_URL and DUMPCAT_MCP_TOKEN in the environment.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md is the whole API reference in Markdown, written by the server itself so it always matches the version you run: authentication, conventions, curl examples and every route with the access it needs. Let an agent read it and call the REST API, or paste it into a chat (API & MCP → Copy Markdown). /api/mcp/tools lists the MCP tools as JSON.

Backup methods

The right tool for each database and size

For MySQL and MariaDB, DumpCat drives mysqldump, mydumper and XtraBackup / MariaBackup. When you add a server, Test connection shows the version, datadir, the size of each database and which methods work on that machine.

mysqldumplogicalmydumperlogical, parallelXtraBackup / MariaBackupphysical, hot
Locks the database?Not for InnoDB, thanks to --single-transactionA global lock for a few milliseconds to sync threads, then noneNo InnoDB locking; a very brief backup lock at the end
Backup speed1 thread per database, several databases in parallelMulti-threaded, tables chunked by rowsFastest: multi-threaded file copy
Restore speedSlowestFast: parallel, indexes built after loadVery fast: file copy + prepare
IncrementalNoNoYes
Restore one database, renameYesYesNo, whole instance
Best forDatabases under 20–50 GBLarge databases restored one at a time100 GB to several TB, low RTO

PostgreSQL 10 and newer: pg_dump per database, with tables dumped and restored in parallel, under a new name or onto another server; pg_basebackup for the whole cluster over a replication connection, with continuous WAL archiving to recover to a time, a restore point or a WAL position.

SQL Server 2012 and newer, on Windows, Linux and in containers: native full and differential backups with BACKUP DATABASE (no client tools to install), restores under a new name or onto another server, restore drills with DBCC CHECKDB, and scheduled log backups for recovery to a point in time, a marked transaction or an LSN. SQL Server writes its backups on its own host: DumpCat reads them from a shared folder, or an agent on that host moves them and nothing is shared.

Storage

One job, copies in several places

Write to local disk and then upload, or stream straight to the cloud with no temporary disk. Each storage keeps its own number of copies, for example 3 backups locally and 30 days on S3.

  • Local / NFSFastest to restore from; keep it off the datadir disk
  • S3AWS, Cloudflare R2, MinIO, Wasabi, DigitalOcean
  • Google DriveOAuth or a Service Account
  • OneDriveSharePoint included
  • FTP / FTPSExplicit or Implicit TLS
  • SFTPPassword or private key
  • WebDAVNextcloud and friends
  • Backblaze B2Plus Azure Blob and Dropbox
  • rclone70+ more backends

      shop.sql.zst.age
      crm.sql.zst.age

Lost the machine running DumpCat? Install a fresh copy, add the storage again and click Import backup catalog: every backup is listed again. Without DumpCat you can still restore with age, zstd and mysql, pg_restore or SQL Server’s RESTORE DATABASE.

Connectivity

Database with no open port? Still backed up.

When the backup server cannot connect to the database directly, because of a firewall, NAT or a database listening on 127.0.0.1 only, let the database host connect out to DumpCat instead. There are two ways, and neither opens a port on the database host. Backups, restores and point-in-time recovery work as with a direct connection.

Agent HTTPS

The database host needs
Outbound HTTPS to DumpCat
Database
Unchanged, even if it listens on 127.0.0.1 only
Install
sudo ./install.sh --agent --server … --key …
Good for
Leaving the network and the MySQL configuration alone

Built-in WireGuard UDP · off by default

The database host needs
Standard WireGuard, outbound UDP 51820 to DumpCat
Database
Listens on the VPN address, the user allows 10.66.0.1
Install
Turn it on on the WireGuard page, copy dumpcat.conf, systemctl enable --now wg-quick@dumpcat
Good for
Teams that already use WireGuard, or a gateway to a whole database network

The database host opens the connection; the data flows both ways inside it. Physical backups (XtraBackup / MariaBackup) work through an agent started with --allow-physical; through WireGuard they still need DumpCat installed on the database host. SQL Server’s backup files also go through an agent, started with --allow-mssql-dir: no shared folder needed.

Operations

The parts you would otherwise script yourself

All of it ships with DumpCat and is switched on and tuned from the web UI.

Encrypted before upload
age (ChaCha20-Poly1305 + scrypt) runs on your server, so the cloud provider cannot read your data.
Integrity checks
SHA-256 for every file. Verify re-reads, decrypts, decompresses and looks for the Dump completed line.
GFS retention
Keep N backups, N days, the last one of each day, week and month. Incremental chains go only with their full.
Careful restores
Every file is test-decrypted before any database is dropped. Restore under new names, or onto another server and version (MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
Accounts and roles
admin, operator, viewer. TOTP two-factor, API tokens, an audit log and lockout after repeated failed logins.
Notifications
Email, Telegram, Slack, Discord and HMAC-signed webhooks, on failure or on success.
Databases behind a firewall
An agent on the database host connects out to DumpCat over HTTPS, or the host joins the built-in WireGuard. No port has to be opened to the database.
Self-update
dumpcat update checks SHA-256, backs up the configuration, waits for running backups and rolls back on failure.

Open source

Free, open source, and your data stays yours

DumpCat is released under the Apache-2.0 license. No account, no license key, no paid edition holding features back: everything on this page is in the build you download.

Apache-2.0 license
Use it at home or at work, modify it and redistribute it. The full text is in LICENSE.
No telemetry
DumpCat sends no usage data anywhere. The only call it makes on its own is reading latest.json once a day to announce new versions, and you can switch that off in Settings.
No middleman
Backups, database passwords and encryption keys travel only from your server to the storage you choose.
Signed releases
Every update is signed with ed25519 and checked against SHA-256 before it is installed. Building it yourself only takes Go.

Build from source

bash
git clone https://github.com/theweakestharrison/DumpCat.git
cd DumpCat
go build -o dumpcat ./cmd/dumpcat
