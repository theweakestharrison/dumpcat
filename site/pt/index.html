Código aberto · Backup e restauração para MySQL, MariaDB, PostgreSQL e SQL Server

Backups que nunca bloqueiam o banco. Recuperação até o segundo exato.

O DumpCat é um único binário com interface web. Ele agenda backups, compacta e criptografa os arquivos, envia cópias para S3, Google Drive, OneDrive ou SFTP, verifica cada uma e traz seus dados de volta quando você precisar. Roda em Linux e Windows, totalmente offline.

Instalação

Rodando em um minuto

Um comando no Linux; no Windows, baixe e dê um duplo clique. O instalador configura um serviço que inicia junto com a máquina e as ferramentas de backup compatíveis com a versão do seu banco; a interface web vem embutida num único arquivo.

No servidor Linux, cole este comando e pressione Enter:

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

Ele baixa a versão mais recente, confere o checksum e instala em /opt/dumpcat como serviço systemd, com rclone, o cliente MySQL/MariaDB, o mariabackup ou XtraBackup compatível e o mydumper quando os repositórios o tiverem; --postgres 16 adiciona as ferramentas cliente do PostgreSQL 16. As opções vão depois de sh -s --: --port 9090, --listen 127.0.0.1, --tls-auto.

  1. Baixe o .zip Baixar para Windows 1.8.0
  2. Descompacte: clique com o botão direito no arquivo e escolha Extract All.
  3. Dê um duplo clique em Install DumpCat e responda Yes. O navegador abre o DumpCat; a janela de instalação mostra o token de configuração.

Windows 10 / 11 ou Windows Server 2016+ 64 bits, roda como serviço do Windows. Prefere PowerShell? Execute irm https://dumpcat.cc/install.ps1 | iex no PowerShell (Administrador). mydumper e XtraBackup para MySQL não estão disponíveis; use o DumpCat no Linux para bancos de centenas de GB.

Novo na linha de comando? Siga o guia passo a passo (em inglês), com soluções para os problemas mais comuns.

Pronto para IA · MCP

Deixe um assistente de IA configurar e vigiar os backups, sem entregar as chaves

O DumpCat é um servidor MCP. Conecte o Claude Code, o Claude Desktop ou qualquer outro cliente MCP com um token de API e peça com suas palavras: o assistente adiciona servidores e armazenamentos, cria jobs e testes de restauração, descobre o que falhou ou está atrasado, lê o log e explica o motivo. Senhas e chaves você mesmo digita na interface web. Outros agentes de IA leem a referência da API em Markdown que o seu próprio servidor escreve para eles.

O que um assistente pode fazer

  • OlharToken somente leitura, o padrãoVisão geral e alertas, jobs, backups, erros e logs, arquivamento de binlog / WAL, resultados de restaurações e testes de restauração, prévias de recuperação point-in-time.
  • IniciarToken de acesso total, operator ou adminExecutar um backup, verificar um backup, iniciar um teste de restauração. O cliente de IA pergunta a você antes de cada um.
  • ConfigurarToken ManageAdicionar servidores e armazenamentos, criar e alterar jobs e testes de restauração. Senhas, chaves e frases secretas nunca passam pelo assistente: ele te dá um link para você mesmo digitá-las.
  • Nunca pelo MCPCom nenhum tokenRestaurações, exclusões e as configurações do sistema. Nenhuma opção libera isso: essas ações ficam só na interface web.

As respostas nunca trazem senhas, chaves ou tokens, e nenhuma ferramenta as recebe; credenciais que aparecem em erros e logs são mascaradas. Cada chamada passa pela API REST com o seu token, então é verificada como qualquer outra requisição e registrada no log de auditoria.

Conecte em um minuto

  1. Crie um tokenPágina API & MCP do DumpCat, New token: Read-only (o padrão) só olha, Full também executa backups, Manage também os configura.
  2. Copie a configuraçãoA página preenche o endereço do seu servidor e o token no comando do Claude Code, na configuração do Claude Desktop e na de outros clientes.
  3. Teste e pergunteTest MCP connection mostra a conta, o acesso e as ferramentas que o assistente vai receber.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

Troque pelo seu endereço e token, ou copie o comando já preenchido na página API & MCP. Para compartilhar o servidor em um projeto sem expor o token, essa página também traz um .mcp.json que lê o token do ambiente.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Abra Settings → Developer → Edit Config, cole e reinicie o Claude Desktop. dumpcat mcp é uma pequena ponte stdio que roda no computador do Claude Desktop; no Linux, command é o caminho do binário dumpcat, e no macOS você compila com Go.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }

O endpoint /api/mcp (streamable HTTP) faz parte do DumpCat, não há mais nada para instalar. Clientes que só iniciam um comando local usam dumpcat mcp, com DUMPCAT_MCP_URL e DUMPCAT_MCP_TOKEN no ambiente.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md é a referência completa da API em Markdown, escrita pelo próprio servidor, então sempre bate com a versão que você roda: autenticação, convenções, exemplos com curl e cada rota com o acesso que exige. Deixe um agente ler e chamar a API REST, ou cole em um chat (API & MCP → Copy Markdown). /api/mcp/tools lista as ferramentas MCP em JSON.

Métodos de backup

A ferramenta certa para cada banco e cada tamanho

Para MySQL e MariaDB, o DumpCat orquestra mysqldump, mydumper e XtraBackup / MariaBackup. Ao adicionar um servidor, Test connection mostra a versão, o datadir, o tamanho de cada banco e quais métodos funcionam naquela máquina.

PostgreSQL 10 ou mais recente: pg_dump por banco, com as tabelas exportadas e restauradas em paralelo, com outro nome ou em outro servidor; pg_basebackup para o cluster inteiro por uma conexão de replicação, com arquivamento contínuo de WAL para recuperar até um horário, um ponto de restauração ou uma posição do WAL.

SQL Server 2012 ou mais recente, no Windows, no Linux e em contêineres: backups nativos completos e diferenciais com BACKUP DATABASE (sem ferramentas cliente), restauração com outro nome ou em outro servidor, testes de restauração com DBCC CHECKDB e backups de log agendados para recuperar até um horário, uma transação marcada ou um LSN. O SQL Server grava os backups no próprio host: o DumpCat os lê de uma pasta compartilhada, ou um agente nesse host os transfere, sem compartilhar nada.

Perdeu a máquina que roda o DumpCat? Instale uma cópia nova, adicione o armazenamento de novo e clique em Import backup catalog: todos os backups voltam para a lista. Sem o DumpCat, você ainda consegue restaurar com age, zstd e mysql, pg_restore ou o RESTORE DATABASE do SQL Server.

Conectividade

Banco sem nenhuma porta aberta? Tem backup do mesmo jeito.

Quando o servidor de backup não consegue se conectar diretamente ao banco, por causa de um firewall, de NAT ou de um banco que só escuta em 127.0.0.1, deixe que o host do banco abra a conexão até o DumpCat. Há duas formas, e nenhuma abre porta no host do banco. Backups, restaurações e recuperação point-in-time funcionam como numa conexão direta.

Agente HTTPS

O host do banco precisa de
HTTPS de saída até o DumpCat
Banco de dados
Inalterado, mesmo que só escute em 127.0.0.1
Instalação
sudo ./install.sh --agent --server … --key …
Ideal para
Não mexer na rede nem na configuração do MySQL

WireGuard integrado UDP · desativado por padrão

O host do banco precisa de
WireGuard padrão, UDP 51820 de saída até o DumpCat
Banco de dados
Escuta no endereço da VPN; o usuário libera o acesso de 10.66.0.1
Instalação
Ative na página WireGuard, copie dumpcat.conf, systemctl enable --now wg-quick@dumpcat
Ideal para
Equipes que já usam WireGuard, ou um gateway para uma rede inteira de bancos

O host do banco abre a conexão; os dados trafegam nos dois sentidos dentro dela. Backups físicos (XtraBackup / MariaBackup) funcionam por um agente iniciado com --allow-physical; pelo WireGuard, eles ainda exigem o DumpCat instalado no host do banco. Os arquivos de backup do SQL Server também passam por um agente iniciado com --allow-mssql-dir, sem pasta compartilhada.

Operações

Tudo aquilo que você faria com scripts caseiros

Tudo isso já vem no DumpCat e é ativado e ajustado pela interface web.

Criptografado antes do upload
O age (ChaCha20-Poly1305 + scrypt) roda no seu servidor, então o provedor de nuvem não consegue ler seus dados.
Verificação de integridade
SHA-256 para cada arquivo. A verificação relê, descriptografa, descompacta e procura a linha Dump completed.
Retenção GFS
Mantenha N backups, N dias, o último de cada dia, semana e mês. Cadeias incrementais só são apagadas junto com o seu backup completo.
Restaurações cuidadosas
Cada arquivo passa por um teste de descriptografia antes de qualquer banco ser apagado. Restaure com novos nomes, ou em outro servidor e outra versão (MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
Contas e papéis
admin, operator, viewer. Dois fatores com TOTP, tokens de API, log de auditoria e bloqueio após repetidas falhas de login.
Notificações
E-mail, Telegram, Slack, Discord e webhooks assinados com HMAC, em caso de falha ou de sucesso.
Bancos atrás de firewall
Um agente no host do banco se conecta ao DumpCat por HTTPS, ou o host entra no WireGuard integrado. Nenhuma porta precisa ser aberta para o banco.
Autoatualização
dumpcat update confere o SHA-256, faz backup da configuração, espera os backups em andamento terminarem e reverte em caso de falha.

Código aberto

Grátis, de código aberto, e seus dados continuam seus

O DumpCat é distribuído sob a licença Apache-2.0. Sem conta, sem chave de licença, sem edição paga segurando recursos: tudo o que está nesta página vem na versão que você baixa.

Use em casa ou no trabalho, modifique e redistribua. O texto completo está em LICENSE.
Sem telemetria
O DumpCat não envia dados de uso para lugar nenhum. A única chamada que ele faz por conta própria é ler o latest.json uma vez por dia para avisar sobre novas versões, e você pode desligar isso nas configurações.
Sem intermediários
Backups, senhas de banco e chaves de criptografia só trafegam do seu servidor para o armazenamento que você escolher.
Versões assinadas
Cada atualização é assinada com ed25519 e conferida com SHA-256 antes de ser instalada. Para compilar você mesmo, basta ter Go.
