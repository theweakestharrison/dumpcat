DumpCat vs Ottomatik

Ottomatik là dịch vụ trực tuyến đăng nhập vào server của bạn qua SSH để chạy và upload backup. DumpCat là công cụ quản lý backup miễn phí, mã nguồn mở, chạy ngay trên server. Dưới đây là khác biệt khi dùng cho MySQL và MariaDB.

Chi tiết từng mục

DumpCatOttomatik
Giá và giấy phépMiễn phí, mã nguồn mở (Apache-2.0). Không cần tài khoản hay license key.Lite $14/tháng (3 job, mỗi ngày, 5 GB), Professional $79 (50 job, mỗi 5 phút, 100 GB, API), Agency $199 (250 job, mỗi phút, 200 GB). Gói nào cũng dùng được storage riêng; dùng thử 14 ngày.
Cách chạyTự host: một file chạy kèm giao diện web, chạy như service systemd hoặc Windows service cạnh database.Dịch vụ SaaS. Máy chủ của họ kết nối tới server của bạn qua SSH và cài Python, pip, AWS CLI lên đó. Một bài hướng dẫn cũng mô tả kiểu backup MySQL từ xa chạy trên máy chủ của Ottomatik, không cần quyền SSH vào server của bạn.
Hệ điều hànhLinux (amd64, arm64) và Windows (64-bit).Server Linux qua SSH (FreeBSD thì cài thủ công). Backup MySQL từ xa chỉ cần thông tin đăng nhập database và cho phép IP của họ kết nối.
DatabaseMySQL 5.7, 8.0, 8.4, Percona Server, MariaDB 10.x và 11.x; PostgreSQL 10 trở lên; Microsoft SQL Server 2012 trở lên (Windows, Linux, container).MySQL, PostgreSQL và MongoDB. Các trang chúng tôi kiểm tra không nói về MariaDB.
Phương thức backupLogical bằng mysqldump / mariadb-dump hoặc mydumper song song; backup vật lý nóng bằng XtraBackup / MariaBackup, có incremental. Không khóa InnoDB. PostgreSQL: pg_dump (các bảng song song) và pg_basebackup (cả cluster). SQL Server: backup full và differential gốc (BACKUP DATABASE, không cần client).mysqldump, có tùy chọn single transaction hoặc bỏ khóa, routines và events.
Khôi phục theo thời điểmCó. Lưu binlog liên tục; khôi phục đến một thời điểm, một vị trí binlog hoặc ngay trước một GTID. PostgreSQL: lưu WAL liên tục; khôi phục đến một thời điểm, một restore point hoặc một vị trí WAL. SQL Server: log backup theo lịch; khôi phục đến một thời điểm, một marked transaction hoặc một LSN.Một phần: binlog được upload lên S3 hoặc chép bằng job backup file; phát lại thì làm thủ công.
Nơi lưu trữỔ local / NFS, S3 và tương thích, Google Drive, OneDrive, SFTP, FTP / FTPS, WebDAV, Backblaze B2, Azure Blob, Dropbox và mọi backend của rclone; nhiều nơi cho một job.Storage của Ottomatik, Amazon S3 và tương thích, Google Drive, Dropbox, Backblaze.
Mã hóaMã hóa age ngay trên server trước khi upload; nén zstd; SHA-256 cho từng file.Thông tin đăng nhập được lưu dạng mã hóa; các trang chúng tôi kiểm tra không nói về việc mã hóa file backup.
Lịch và retentionLịch kiểu cron; retention riêng cho từng nơi lưu theo số bản, số ngày hoặc GFS (ngày / tuần / tháng).Từ mỗi ngày (Lite) đến mỗi phút (Agency); số job và dung lượng giới hạn theo gói. Mỗi job giữ một số bản nhất định và tự xóa các bản cũ hơn.
Khôi phụcNgay trên giao diện web: restore sang tên database mới, thử giải mã mọi file trước khi xóa gì, kiểm tra toàn vẹn sau mỗi lần chạy.Khôi phục một cú nhấp về cùng server hoặc server khác, ở một số gói.
Dữ liệu đi đâuĐi thẳng từ server của bạn tới nơi lưu bạn chọn, không qua bên thứ ba nào.Khi dùng SSH, bản backup đi thẳng từ server của bạn tới storage. Backup MySQL từ xa được xử lý trên máy chủ của Ottomatik, nên dữ liệu đi qua họ. Ottomatik giữ (dạng mã hóa) thông tin đăng nhập SSH, database và storage.
Thông báoEmail, Telegram, Slack, Discord và webhook ký HMAC.Thông báo khi job thành công hoặc thất bại, và webhook gửi trạng thái job; phân quyền nhóm trên bảng điều khiển.

Chọn Ottomatik nếu

  • Bạn muốn phần lên lịch và theo dõi chạy bên ngoài server, không phải tự cập nhật gì.
  • Bạn backup cả PostgreSQL và MongoDB và muốn chung một bảng điều khiển.
  • Bạn muốn backup dày tới mỗi phút và khôi phục một cú nhấp sang server khác.

Chọn DumpCat nếu

  • Bạn không muốn cấp quyền SSH vào server database cho bên thứ ba.
  • Bạn muốn khôi phục theo thời điểm ngay trên giao diện thay vì tự phát lại binlog.
  • Bạn dùng server Windows, hoặc cần backup vật lý nóng cho database lớn.
  • Bạn muốn miễn phí, không giới hạn số job hay dung lượng.

Chuyển từ Ottomatik sang DumpCat

  1. Cài DumpCat trên server database.
  2. Thêm storage S3, Google Drive hoặc Dropbox vào DumpCat, trong một thư mục mới.
  3. Tạo lại từng job với lịch và retention, bật lưu binlog, rồi chạy thử một lần.
  4. Khi retention của DumpCat đã đủ, xóa SSH key của Ottomatik khỏi server.

So sánh khác

  • DumpCat vs SQLBackupAndFTPỨng dụng backup trên Windows cho SQL Server, MySQL, MariaDB và PostgreSQL, bản quyền theo máy.
  • DumpCat vs SimpleBackupsDịch vụ trực tuyến backup server, database và storage, từ gói miễn phí đến $299/tháng.
  • DumpCat vs DatabasusỨng dụng web backup nhiều loại database, mã nguồn mở (trước là Postgresus); với MySQL chỉ backup logical.
  • DumpCat vs SqlBakDịch vụ backup dùng agent, của nhà làm SQLBackupAndFTP, tính phí theo server.
  • DumpCat vs AutoMySQLBackupScript cron kinh điển, xoay vòng theo ngày / tuần / tháng; dự án gốc dừng từ 2011.
  • DumpCat vs Percona XtraBackupEngine backup vật lý nóng mã nguồn mở. DumpCat chạy nó giúp bạn, kèm lịch, nơi lưu và khôi phục.
  • DumpCat vs MySQL Enterprise BackupCông cụ backup vật lý thương mại của Oracle, nằm trong MySQL Enterprise Edition.
  • DumpCat vs SnapShooterDịch vụ backup thuộc DigitalOcean; lần cập nhật sản phẩm gần nhất được liệt kê là tháng 9/2024.
  • DumpCat vs NavicatPhần mềm quản trị database trả phí phổ biến; backup là tính năng phụ, lưu local, chạy theo lịch.
  • DumpCat vs BackupSheepTừng là SaaS, nay là bản beta mã nguồn mở tự host cho database, snapshot cloud và WordPress.
