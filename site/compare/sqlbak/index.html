DumpCat vs SqlBak

SqlBak, from Pranas.NET (the makers of SQLBackupAndFTP), puts an agent on each server and manages it from a cloud dashboard. DumpCat is a free, open-source backup manager that runs entirely on your own server. Here is how they compare for MySQL and MariaDB.

Choose SqlBak if

  • You manage many servers and want one cloud dashboard that also warns you when a server stops responding.
  • You want automatic restores to another server, for example to keep a test copy up to date.

Choose DumpCat if

  • Your databases are large: DumpCat adds parallel mydumper and hot physical backups with XtraBackup / MariaBackup, including incrementals.
  • You run MySQL 8.4 or MariaDB 11, which DumpCat supports explicitly.
  • You want no per-server fee and no account: every storage type and encryption is included for free.
  • The server is on an isolated network, or you do not want a third-party dashboard involved at all.

Switching from SqlBak

  1. Install DumpCat on each database server.
  2. Add your existing storage (S3, Google Drive, SFTP…) to DumpCat, in a new folder.
  3. Recreate the backup jobs, and turn on binlog archiving if you used SqlBak's point-in-time backups.
  4. Run each job once and check the integrity result, then remove the SqlBak agent when DumpCat's retention covers what you need.
