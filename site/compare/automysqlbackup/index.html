DumpCat vs AutoMySQLBackup

AutoMySQLBackup is the bash script many servers still run from cron. Its original SourceForge project last released in 2011; Debian still packages version 2.6 and a GitHub fork keeps it alive. DumpCat does the same job with a web UI, remote storage and point-in-time recovery.

Choose AutoMySQLBackup if

  • You want the smallest possible thing: one script and a cron line on a server where a local copy is enough.
  • It already runs, and you only need nightly local dumps.

Choose DumpCat if

  • You want backups off the server: S3, Google Drive, OneDrive, SFTP and more, several per job with their own retention.
  • You want to restore from a web UI, into a new database name, with every file test-decrypted first.
  • You need point-in-time recovery or hot physical backups for large databases.
  • You want failure alerts on Telegram, Slack or Discord and a project that is actively maintained.

Switching from AutoMySQLBackup

  1. Install DumpCat on the server; the Linux installer also installs the backup tools that match your database.
  2. Add a local storage pointing to a new directory, plus at least one remote storage.
  3. Create a job with the same databases; set retention to match your daily / weekly / monthly rotation (GFS).
  4. Run it once, check the integrity result, then remove the AutoMySQLBackup cron line.
