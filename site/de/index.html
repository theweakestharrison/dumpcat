KILassen Sie Claude Ihre Backups einrichten und prüfen

Open Source · Backup & Wiederherstellung für MySQL, MariaDB, PostgreSQL und SQL Server

Backups ohne Datenbanksperre. Wiederherstellung auf die Sekunde genau.

DumpCat ist eine einzige Binärdatei mit Weboberfläche. Es plant Backups, komprimiert und verschlüsselt sie, überträgt Kopien zu S3, Google Drive, OneDrive oder per SFTP, prüft sie und holt Ihre Daten zurück, wenn Sie sie brauchen. Läuft unter Linux und Windows, vollständig offline.

Installation

In einer Minute startklar

Unter Linux ein einziger Befehl, unter Windows herunterladen und doppelklicken. Der Installer richtet einen Dienst ein, der mit dem Rechner startet, dazu die Backup-Tools passend zu Ihrer Datenbankversion; die Weboberfläche steckt mit in einer einzigen Datei.

Fügen Sie auf dem Linux-Server diesen Befehl ein und drücken Sie Enter:

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

Er lädt das neueste Release herunter, prüft die Prüfsumme und installiert es als systemd-Dienst nach /opt/dumpcat, zusammen mit rclone, dem MySQL/MariaDB-Client, dem passenden mariabackup oder XtraBackup und mydumper, sofern die Paketquellen es anbieten; --postgres 16 fügt die Client-Tools von PostgreSQL 16 hinzu. Optionen kommen hinter sh -s --: --port 9090, --listen 127.0.0.1, --tls-auto.

  1. Die .zip-Datei herunterladen Für Windows herunterladen 1.8.0
  2. Entpacken: Rechtsklick auf die Datei, Extract All („Alle extrahieren“) wählen.
  3. Doppelklick auf Install DumpCat, dann mit Yes („Ja“) bestätigen. Ihr Browser öffnet DumpCat; das Installationsfenster zeigt das Setup-Token.

Windows 10 / 11 oder Windows Server 2016+ 64-Bit, läuft als Windows-Dienst. Lieber PowerShell? Führen Sie irm https://dumpcat.cc/install.ps1 | iex in PowerShell (als Administrator) aus. mydumper und XtraBackup für MySQL sind nicht verfügbar; für Datenbanken mit Hunderten von GB betreiben Sie DumpCat unter Linux.

Neu auf der Kommandozeile? Folgen Sie der Schritt-für-Schritt-Anleitung (auf Englisch), mit Lösungen für häufige Probleme.

KI-freundlich · MCP

Ein KI-Assistent richtet die Backups ein und behält sie im Blick, ohne dass Sie ihm die Schlüssel geben

DumpCat ist ein MCP-Server. Verbinden Sie Claude Code, Claude Desktop oder einen anderen MCP-Client mit einem API-Token und sagen Sie in normalen Worten, was Sie brauchen: Der Assistent legt Server und Speicher an, erstellt Jobs und Wiederherstellungstests, sieht nach, was fehlgeschlagen oder überfällig ist, liest das Log und erklärt die Ursache. Passwörter und Schlüssel geben Sie selbst in der Weboberfläche ein. Andere KI-Agenten lesen die API-Referenz in Markdown, die Ihr eigener Server für sie schreibt.

Was ein Assistent darf

  • NachsehenNur-Lese-Token, die VoreinstellungÜbersicht und Warnungen, Jobs, Backups, Fehler und Logs, Binlog- / WAL-Archivierung, Ergebnisse von Wiederherstellungen und Wiederherstellungstests, Vorschauen der Point-in-Time-Recovery.
  • StartenToken mit Vollzugriff, operator oder adminEin Backup ausführen, ein Backup verifizieren, einen Wiederherstellungstest starten. Der KI-Client fragt Sie jedes Mal vorher.
  • EinrichtenManage-TokenServer und Speicher hinzufügen, Jobs und Wiederherstellungstests anlegen und ändern. Passwörter, Schlüssel und Passphrasen laufen nie über den Assistenten: Er gibt Ihnen einen Link, unter dem Sie sie selbst eingeben.
  • Niemals über MCPMit keinem TokenWiederherstellungen, Löschungen und die Einstellungen von DumpCat. Keine Option schaltet sie frei: Das bleibt der Weboberfläche vorbehalten.

Antworten enthalten nie Passwörter, Schlüssel oder Tokens, und kein Tool nimmt sie entgegen; Zugangsdaten in Fehlermeldungen und Logs werden maskiert. Jeder Aufruf läuft mit Ihrem Token über die REST-API, wird also wie jede andere Anfrage geprüft und im Audit-Log festgehalten.

In einer Minute verbunden

  1. Token anlegenSeite API & MCP in DumpCat, New token: Read-only (Voreinstellung) sieht nur nach, Full startet auch Backups, Manage richtet sie auch ein.
  2. Konfiguration kopierenDie Seite trägt die Adresse Ihres Servers und den Token in den Befehl für Claude Code, die Konfiguration für Claude Desktop und die für andere Clients ein.
  3. Testen, dann fragenTest MCP connection zeigt das Konto, den Zugriff und die Tools, die der Assistent bekommt.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

Setzen Sie Ihre eigene Adresse und Ihren Token ein, oder kopieren Sie den ausgefüllten Befehl von der Seite API & MCP. Um den Server ohne Token in einem Projekt zu teilen, bietet die Seite auch eine .mcp.json, die den Token aus der Umgebung liest.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Öffnen Sie Settings → Developer → Edit Config, fügen Sie ein und starten Sie Claude Desktop neu. dumpcat mcp ist eine kleine stdio-Brücke, die auf dem Rechner mit Claude Desktop läuft; unter Linux ist command der Pfad zum dumpcat-Programm, unter macOS bauen Sie es selbst mit Go.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }
  }
}

Der Endpunkt /api/mcp (streamable HTTP) ist Teil von DumpCat, es muss nichts weiter installiert werden. Clients, die nur einen lokalen Befehl starten, nutzen dumpcat mcp mit DUMPCAT_MCP_URL und DUMPCAT_MCP_TOKEN in der Umgebung.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md ist die vollständige API-Referenz in Markdown, vom Server selbst geschrieben und daher immer passend zur laufenden Version: Authentifizierung, Konventionen, curl-Beispiele und jede Route mit dem nötigen Zugriff. Lassen Sie einen Agenten sie lesen und die REST-API aufrufen, oder fügen Sie sie in einen Chat ein (API & MCP → Copy Markdown). /api/mcp/tools listet die MCP-Tools als JSON.

Backup-Methoden

Das passende Werkzeug für jede Datenbank und jede Größe

Für MySQL und MariaDB steuert DumpCat mysqldump, mydumper und XtraBackup / MariaBackup. Wenn Sie einen Server hinzufügen, zeigt Test connection die Version, das Datadir, die Größe jeder Datenbank und welche Methoden auf diesem Rechner funktionieren.

PostgreSQL ab Version 10: pg_dump pro Datenbank, wobei Tabellen parallel gesichert und wiederhergestellt werden, auch unter neuem Namen oder auf einem anderen Server; pg_basebackup für den ganzen Cluster über eine Replikationsverbindung, mit kontinuierlicher WAL-Archivierung zur Wiederherstellung auf einen Zeitpunkt, einen Wiederherstellungspunkt oder eine WAL-Position.

SQL Server ab 2012, unter Windows, Linux und in Containern: native Voll- und differenzielle Backups mit BACKUP DATABASE (ohne Client-Tools), Wiederherstellung unter neuem Namen oder auf einem anderen Server, Wiederherstellungstests mit DBCC CHECKDB und geplante Log-Backups zur Wiederherstellung auf einen Zeitpunkt, eine markierte Transaktion oder eine LSN. SQL Server schreibt seine Backups auf dem eigenen Host: DumpCat liest sie aus einem freigegebenen Ordner, oder ein Agent auf diesem Host überträgt sie, ganz ohne Freigabe.

Verbindung

Datenbank ohne offenen Port? Wird trotzdem gesichert.

Wenn der Backup-Server die Datenbank nicht direkt erreicht, etwa wegen einer Firewall, NAT oder weil die Datenbank nur auf 127.0.0.1 lauscht, baut stattdessen der Datenbank-Host die Verbindung zu DumpCat auf. Dafür gibt es zwei Wege, und keiner öffnet einen Port auf dem Datenbank-Host. Backups, Wiederherstellungen und Point-in-Time-Recovery funktionieren wie bei einer direkten Verbindung.

Agent HTTPS

Der Datenbank-Host braucht
Ausgehendes HTTPS zu DumpCat
Datenbank
Unverändert, auch wenn sie nur auf 127.0.0.1 lauscht
Installation
sudo ./install.sh --agent --server … --key …
Ideal für
Umgebungen, in denen Netzwerk und MySQL-Konfiguration unangetastet bleiben sollen

Integriertes WireGuard UDP · standardmäßig aus

Der Datenbank-Host braucht
Standard-WireGuard, ausgehend UDP 51820 zu DumpCat
Datenbank
Lauscht auf der VPN-Adresse, der Benutzer erlaubt 10.66.0.1
Installation
Auf der WireGuard-Seite einschalten, dumpcat.conf kopieren, systemctl enable --now wg-quick@dumpcat
Ideal für
Teams, die WireGuard bereits nutzen, oder als Gateway zu einem ganzen Datenbanknetz

Der Datenbank-Host öffnet die Verbindung; die Daten fließen darin in beide Richtungen. Physische Backups (XtraBackup / MariaBackup) funktionieren über einen Agenten, der mit --allow-physical gestartet wurde; über WireGuard muss DumpCat dafür weiterhin auf dem Datenbank-Host installiert sein. Auch die Backup-Dateien von SQL Server laufen über einen Agenten, der mit --allow-mssql-dir gestartet wurde: Ein freigegebener Ordner ist nicht nötig.

Betrieb

Was Sie sonst selbst skripten müssten

All das ist in DumpCat enthalten und wird in der Weboberfläche eingeschaltet und eingestellt.

Vor dem Upload verschlüsselt
age (ChaCha20-Poly1305 + scrypt) läuft auf Ihrem Server, daher kann der Cloud-Anbieter Ihre Daten nicht lesen.
Integritätsprüfungen
SHA-256 für jede Datei. Die Verifizierung liest erneut, entschlüsselt, entpackt und sucht nach der Zeile Dump completed.
GFS-Aufbewahrung
N Backups, N Tage, jeweils das letzte jedes Tages, jeder Woche und jedes Monats. Inkrementelle Ketten werden nur zusammen mit ihrem Vollbackup gelöscht.
Umsichtige Wiederherstellung
Jede Datei wird probeweise entschlüsselt, bevor irgendeine Datenbank gelöscht wird. Wiederherstellung unter neuen Namen oder auf einen anderen Server und eine andere Version (MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
Konten und Rollen
admin, operator, viewer. TOTP-Zwei-Faktor-Authentifizierung, API-Tokens, ein Audit-Log und Sperre nach wiederholt fehlgeschlagenen Anmeldungen.
Benachrichtigungen
E-Mail, Telegram, Slack, Discord und HMAC-signierte Webhooks, bei Fehlern oder bei Erfolg.
Datenbanken hinter einer Firewall
Ein Agent auf dem Datenbank-Host verbindet sich ausgehend per HTTPS mit DumpCat, oder der Host tritt dem integrierten WireGuard bei. Zur Datenbank muss kein Port geöffnet werden.
Selbst-Update
dumpcat update prüft SHA-256, sichert die Konfiguration, wartet laufende Backups ab und rollt bei einem Fehler zurück.

Open Source

Kostenlos, Open Source, und Ihre Daten gehören Ihnen

DumpCat steht unter der Apache-2.0-Lizenz. Kein Konto, kein Lizenzschlüssel, keine kostenpflichtige Edition, die Funktionen zurückhält: Alles auf dieser Seite steckt in dem Build, den Sie herunterladen.

Apache-2.0-Lizenz
Nutzen Sie es privat oder im Unternehmen, ändern Sie es und geben Sie es weiter. Der vollständige Text steht in LICENSE.
Keine Telemetrie
DumpCat sendet keinerlei Nutzungsdaten. Die einzige Verbindung, die es von sich aus aufbaut, ist der tägliche Abruf von latest.json, um neue Versionen anzukündigen, und den können Sie in den Einstellungen abschalten.
Kein Umweg über Dritte
Backups, Datenbankpasswörter und Verschlüsselungsschlüssel gelangen nur von Ihrem Server zu dem Speicher, den Sie wählen.
Signierte Releases
Jedes Update ist mit ed25519 signiert und wird vor der Installation gegen SHA-256 geprüft. Zum Selbstbauen brauchen Sie nur Go.

Aus dem Quellcode bauen

bash
git clone https://github.com/theweakestharrison/DumpCat.git
cd DumpCat
