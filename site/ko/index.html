데이터베이스를 잠그지 않는 백업. 1초 단위까지 정확한 복구.

DumpCat은 웹 UI를 갖춘 단일 바이너리입니다. 백업을 예약하고, 압축하고 암호화해 S3, Google Drive, OneDrive, SFTP로 사본을 보내고, 검증까지 마친 뒤, 필요할 때 데이터를 되살려 줍니다. Linux와 Windows에서 완전히 오프라인으로 동작합니다.

설치

1분 만에 실행

Linux에서는 명령어 한 줄, Windows에서는 다운로드 후 더블클릭이면 됩니다. 설치 프로그램이 부팅과 함께 시작되는 서비스와, 데이터베이스 버전에 맞는 백업 도구를 설치합니다. 웹 UI는 파일 하나에 내장되어 있습니다.

Linux 서버에서 이 명령어를 붙여 넣고 Enter 키를 누르세요:

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

최신 릴리스를 내려받아 체크섬을 확인한 뒤, /opt/dumpcat에 systemd 서비스로 설치합니다. rclone, MySQL/MariaDB 클라이언트, 버전에 맞는 mariabackup 또는 XtraBackup, 그리고 저장소에 있으면 mydumper도 함께 설치합니다. --postgres 16을 붙이면 PostgreSQL 16 클라이언트 도구가 추가됩니다. 옵션은 sh -s -- 뒤에 붙입니다: --port 9090, --listen 127.0.0.1, --tls-auto.

  1. .zip 다운로드 Windows용 다운로드 1.8.0
  2. 압축 풀기: 파일을 마우스 오른쪽 버튼으로 클릭하고 Extract All을 선택합니다.
  3. Install DumpCat을 더블클릭하고 Yes를 누릅니다. 브라우저에서 DumpCat이 열리고, 설치 창에 설정 토큰이 표시됩니다.

Windows 10 / 11 또는 Windows Server 2016+ 64비트에서 Windows 서비스로 실행됩니다. PowerShell이 편하신가요? PowerShell(관리자)에서 irm https://dumpcat.cc/install.ps1 | iex를 실행하세요. MySQL용 mydumper와 XtraBackup은 제공되지 않으므로, 수백 GB 규모의 데이터베이스라면 Linux에서 DumpCat을 실행하세요.

명령줄이 처음이신가요? 단계별 가이드(영문)를 따라 해 보세요. 자주 겪는 문제의 해결 방법도 담겨 있습니다.

AI 친화적 · MCP

백업 구성과 감시는 AI 어시스턴트에게, 열쇠는 넘기지 않고

DumpCat은 MCP 서버입니다. Claude Code, Claude Desktop 또는 다른 MCP 클라이언트를 API 토큰으로 연결하고 평소 말투로 부탁하세요. 어시스턴트가 서버와 스토리지를 추가하고, 작업과 복원 훈련을 만들고, 실패했거나 밀린 백업을 찾아 로그를 읽고 원인을 알려 줍니다. 비밀번호와 키는 웹 UI에서 직접 입력합니다. 다른 AI 에이전트는 서버가 직접 만들어 주는 Markdown API 레퍼런스를 읽습니다.

AI 어시스턴트가 할 수 있는 일

  • 보기읽기 전용 토큰, 기본값개요와 경고, 작업, 백업, 오류와 로그, binlog / WAL 보관, 복원과 복원 훈련 결과, 특정 시점 복구 미리 보기.
  • 시작하기전체 권한 토큰, operator 또는 admin백업 실행, 백업 검증, 복원 훈련 시작. AI 클라이언트가 매번 먼저 물어봅니다.
  • 구성하기Manage 토큰서버와 스토리지 추가, 작업과 복원 훈련의 생성과 변경. 비밀번호, 키, 패스프레이즈는 어시스턴트를 거치지 않으며, 직접 입력할 수 있는 링크를 알려 줍니다.
  • MCP로는 절대 불가어떤 토큰이든복원, 삭제, DumpCat 설정. 켜는 옵션도 없습니다. 이런 작업은 웹 UI에서만 합니다.

답변에는 비밀번호, 키, 토큰이 절대 들어가지 않으며 이를 받는 도구도 없습니다. 오류와 로그에 섞인 자격 증명도 가려집니다. 모든 호출은 여러분의 토큰으로 REST API를 거치므로 다른 요청과 똑같이 권한이 확인되고 감사 로그에 기록됩니다.

1분이면 연결

  1. 토큰 만들기DumpCat의 API & MCP 페이지에서 New token. Read-only(기본값)는 보기만, Full은 백업 실행까지, Manage는 백업 구성까지 할 수 있습니다.
  2. 설정 복사그 페이지가 서버 주소와 토큰을 채워 Claude Code 명령, Claude Desktop 설정, 다른 클라이언트용 설정을 보여 줍니다.
  3. 테스트하고 질문하기Test MCP connection이 어시스턴트가 받게 될 계정, 권한, 도구를 보여 줍니다.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

주소와 토큰을 여러분의 것으로 바꾸거나, API & MCP 페이지에서 값이 채워진 명령을 복사하세요. 토큰을 드러내지 않고 프로젝트에서 공유하려면, 같은 페이지에 환경 변수에서 토큰을 읽는 .mcp.json도 있습니다.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Settings → Developer → Edit Config를 열어 붙여 넣고 Claude Desktop을 다시 시작하세요. dumpcat mcp는 Claude Desktop이 있는 컴퓨터에서 실행되는 작은 stdio 브리지입니다. Linux에서는 command에 dumpcat 실행 파일 경로를 넣고, macOS에서는 Go로 직접 빌드합니다.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }
  }
}

엔드포인트 /api/mcp(streamable HTTP)는 DumpCat에 들어 있어 따로 설치할 것이 없습니다. 로컬 명령만 실행할 수 있는 클라이언트는 환경 변수 DUMPCAT_MCP_URL과 DUMPCAT_MCP_TOKEN을 설정하고 dumpcat mcp를 사용합니다.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md는 Markdown으로 된 전체 API 레퍼런스입니다. 서버가 직접 만들기 때문에 실행 중인 버전과 항상 일치합니다. 인증, 규칙, curl 예시, 그리고 각 라우트에 필요한 권한까지 담겨 있습니다. 에이전트가 읽고 REST API를 호출하게 하거나, 채팅에 붙여 넣으세요(API & MCP → Copy Markdown). /api/mcp/tools는 MCP 도구를 JSON으로 나열합니다.

백업 방식

데이터베이스와 규모에 꼭 맞는 도구

MySQL과 MariaDB에서는 DumpCat이 mysqldump, mydumper, XtraBackup / MariaBackup을 구동합니다. 서버를 추가할 때 Test connection을 누르면 버전, datadir, 데이터베이스별 크기, 그리고 그 서버에서 쓸 수 있는 방식이 표시됩니다.

mysqldump논리mydumper논리, 병렬XtraBackup / MariaBackup물리, 핫 백업
데이터베이스를 잠그나요?--single-transaction 덕분에 InnoDB는 잠그지 않음스레드 동기화를 위해 몇 밀리초 동안 전역 잠금, 이후에는 없음InnoDB 잠금 없음, 마지막에 아주 짧은 백업 잠금
백업 속도데이터베이스당 스레드 1개, 여러 데이터베이스를 병렬로멀티스레드, 테이블을 행 단위로 분할가장 빠름: 멀티스레드 파일 복사
복원 속도가장 느림빠름: 병렬, 적재 후 인덱스 생성매우 빠름: 파일 복사 + prepare
증분 백업미지원미지원지원
데이터베이스 하나만 복원, 이름 변경가능가능불가, 인스턴스 전체만
적합한 용도20–50 GB 미만의 데이터베이스하나씩 복원하는 대용량 데이터베이스100 GB에서 수 TB까지, 짧은 RTO

PostgreSQL 10 이상: 데이터베이스별 pg_dump로 테이블을 병렬로 덤프하고 복원하며, 새 이름으로 또는 다른 서버에 복원할 수 있습니다. 클러스터 전체는 복제 연결을 통한 pg_basebackup으로 백업하고, 연속 WAL 아카이빙으로 특정 시각, 복원 지점(restore point), WAL 위치까지 복구합니다.

SQL Server 2012 이상(Windows, Linux, 컨테이너): BACKUP DATABASE를 이용한 네이티브 전체 백업과 차등 백업(클라이언트 도구 불필요), 새 이름으로 또는 다른 서버에 복원, DBCC CHECKDB를 포함한 복원 훈련, 그리고 예약된 로그 백업으로 특정 시각, 표시된 트랜잭션, LSN까지 복구합니다. SQL Server는 백업을 자기 호스트에 쓰므로, DumpCat이 공유 폴더에서 읽거나, 공유 없이 그 호스트의 에이전트가 파일을 옮겨 줍니다.

스토리지

작업 하나로 여러 곳에 사본을

로컬 디스크에 쓴 뒤 업로드하거나, 임시 디스크 없이 클라우드로 바로 스트리밍합니다. 스토리지마다 보관할 사본 수를 따로 정할 수 있습니다. 예를 들어 로컬에는 백업 3개, S3에는 30일 치를 둘 수 있습니다.

  • 로컬 / NFS가장 빠르게 복원, datadir와는 다른 디스크에 두세요
  • S3AWS, Cloudflare R2, MinIO, Wasabi, DigitalOcean
  • Google DriveOAuth 또는 서비스 계정
  • OneDriveSharePoint 포함
  • FTP / FTPS명시적 또는 암시적 TLS
  • SFTP비밀번호 또는 개인 키
  • WebDAVNextcloud 등
  • Backblaze B2Azure Blob, Dropbox도 지원
  • rclone70개 이상의 백엔드 추가 지원

DumpCat을 실행하던 머신을 잃었나요? 새로 설치하고 스토리지를 다시 추가한 뒤 Import backup catalog를 누르면 모든 백업이 다시 목록에 나타납니다. DumpCat 없이도 age, zstd와 mysql, pg_restore 또는 SQL Server의 RESTORE DATABASE로 복원할 수 있습니다.

연결

열린 포트가 없는 데이터베이스? 그래도 백업됩니다.

방화벽이나 NAT 때문에, 또는 데이터베이스가 127.0.0.1에서만 수신 대기해서 백업 서버가 데이터베이스에 직접 연결할 수 없다면, 반대로 데이터베이스 호스트가 DumpCat으로 연결하게 하세요. 방법은 두 가지이며, 어느 쪽도 데이터베이스 호스트에 포트를 열지 않습니다. 백업, 복원, 특정 시점 복구는 직접 연결할 때와 똑같이 동작합니다.

적합한 경우
이미 WireGuard를 쓰는 팀, 또는 데이터베이스 네트워크 전체로 가는 게이트웨이

연결은 데이터베이스 호스트가 열고, 데이터는 그 연결 안에서 양방향으로 흐릅니다. 물리 백업(XtraBackup / MariaBackup)은 --allow-physical로 시작한 에이전트를 통해 동작하며, WireGuard를 통할 때는 여전히 데이터베이스 호스트에 DumpCat을 설치해야 합니다. SQL Server의 백업 파일도 --allow-mssql-dir로 시작한 에이전트가 옮겨 주므로 공유 폴더가 필요 없습니다.

운영

원래라면 직접 스크립트로 짜야 했을 것들

모두 DumpCat에 기본으로 들어 있고, 웹 UI에서 켜고 조정합니다.

업로드 전에 암호화
age(ChaCha20-Poly1305 + scrypt)가 사용자의 서버에서 실행되므로 클라우드 제공자는 데이터를 읽을 수 없습니다.
무결성 검사
모든 파일에 SHA-256. 검증(Verify)은 파일을 다시 읽어 복호화하고 압축을 푼 뒤 Dump completed 줄이 있는지 확인합니다.
GFS 보존 정책
백업 N개, N일, 그리고 일·주·월마다 마지막 백업 하나씩 보관합니다. 증분 체인은 해당 전체 백업과 함께만 삭제됩니다.
신중한 복원
데이터베이스를 DROP하기 전에 모든 파일을 시험 복호화합니다. 새 이름으로, 또는 다른 서버와 다른 버전으로 복원할 수 있습니다(MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
계정과 역할
admin, operator, viewer. TOTP 2단계 인증, API 토큰, 감사 로그, 로그인이 반복해서 실패하면 계정 잠금.
알림
이메일, Telegram, Slack, Discord, HMAC 서명 웹훅으로 실패 시 또는 성공 시 알려 줍니다.
방화벽 뒤의 데이터베이스
데이터베이스 호스트의 에이전트가 HTTPS로 DumpCat에 연결하거나, 호스트가 내장 WireGuard에 참여합니다. 데이터베이스 쪽에 포트를 열 필요가 없습니다.
자체 업데이트
dumpcat update는 SHA-256을 확인하고, 설정을 백업하고, 실행 중인 백업이 끝나기를 기다렸다가, 실패하면 롤백합니다.

오픈 소스

무료 오픈 소스, 데이터는 오롯이 당신의 것

DumpCat은 Apache-2.0 라이선스로 배포됩니다. 계정도, 라이선스 키도, 기능을 묶어 둔 유료 에디션도 없습니다. 이 페이지에 나온 모든 기능이 내려받는 빌드에 들어 있습니다.

Apache-2.0 라이선스
집에서든 회사에서든 사용하고, 수정하고, 재배포할 수 있습니다. 전문은 LICENSE에 있습니다.
텔레메트리 없음
DumpCat은 사용 데이터를 어디에도 보내지 않습니다. 스스로 하는 유일한 호출은 새 버전을 알리기 위해 하루 한 번 latest.json을 읽는 것이며, 설정(Settings)에서 끌 수 있습니다.
중개자 없음
백업, 데이터베이스 비밀번호, 암호화 키는 사용자의 서버에서 사용자가 고른 스토리지로만 이동합니다.
서명된 릴리스
모든 업데이트는 ed25519로 서명되며, 설치 전에 SHA-256으로 검증됩니다. 직접 빌드하려면 Go만 있으면 됩니다.

소스에서 빌드하기

bash
git clone https://github.com/theweakestharrison/DumpCat.git
cd DumpCat
go build -o dumpcat ./cmd/dumpcat
