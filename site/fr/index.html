MCPCompatible IA : demandez à Claude ou à un autre assistant IA où en sont vos sauvegardes

Open source · Sauvegarde et restauration pour MySQL, MariaDB et PostgreSQL

Sauvegardez sans jamais verrouiller la base. Restaurez à la seconde près.

DumpCat est un binaire unique doté d’une interface web. Il planifie les sauvegardes, les compresse et les chiffre, en envoie des copies vers S3, Google Drive, OneDrive ou SFTP, les vérifie et restaure vos données le moment venu. Fonctionne sous Linux et Windows, entièrement hors ligne.

Installation

Opérationnel en une minute

Une commande sous Linux, un téléchargement et un double-clic sous Windows. L’installateur met en place un service qui démarre avec la machine, ainsi que les outils de sauvegarde adaptés à la version de votre base ; l’interface web est intégrée dans un seul fichier.

Sur le serveur Linux, collez cette commande et appuyez sur Entrée :

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

Elle télécharge la dernière version, vérifie sa somme de contrôle et l’installe dans /opt/dumpcat comme service systemd, avec rclone, le client MySQL/MariaDB, le mariabackup ou XtraBackup correspondant, et mydumper s’il est dans les dépôts ; --postgres 16 ajoute les outils client de PostgreSQL 16. Les options se placent après sh -s -- : --port 9090, --listen 127.0.0.1, --tls-auto.

  1. Téléchargez le .zip Télécharger pour Windows 1.6.0
  2. Décompressez-le : clic droit sur le fichier, puis Extract All (Extraire tout).
  3. Double-cliquez sur Install DumpCat et répondez Yes (Oui). Votre navigateur ouvre DumpCat ; la fenêtre d’installation affiche le jeton de configuration.

Windows 10 / 11 ou Windows Server 2016+ 64 bits, fonctionne comme service Windows. Vous préférez PowerShell ? Lancez irm https://dumpcat.cc/install.ps1 | iex dans PowerShell (administrateur). mydumper et XtraBackup pour MySQL ne sont pas disponibles ; faites tourner DumpCat sous Linux pour des bases de plusieurs centaines de Go.

Peu habitué à la ligne de commande ? Suivez le guide pas à pas (en anglais), avec des solutions aux problèmes courants.

Compatible IA · MCP

Confiez la surveillance des sauvegardes à un assistant IA, sans lui donner les clés

DumpCat est un serveur MCP. Connectez Claude Code, Claude Desktop ou un autre client MCP avec un jeton d’API, puis posez vos questions en langage courant : l’assistant cherche ce qui a échoué ou pris du retard, lit le journal et vous explique pourquoi. Les autres agents IA lisent la référence d’API en Markdown que votre propre serveur rédige pour eux.

Ce qu’un assistant peut faire

  • RegarderJeton en lecture seule, par défautVue d’ensemble et alertes, tâches, sauvegardes, erreurs et journaux, archivage binlog / WAL, résultats des restaurations et des exercices, aperçus de restauration à un instant précis.
  • LancerJeton à accès complet, operator ou adminLancer une sauvegarde, vérifier une sauvegarde, démarrer un exercice de restauration. Le client IA vous demande avant chaque action.
  • Jamais via MCPQuel que soit le jetonRestaurations, suppressions, identifiants et réglages. Aucune option ne les active : tout cela se fait dans l’interface web.

Les réponses ne contiennent jamais de mots de passe, de clés ni de jetons, et les identifiants présents dans les erreurs et les journaux sont masqués. Chaque appel passe par l’API REST avec votre jeton : il est donc contrôlé comme n’importe quelle requête et inscrit au journal d’audit.

Connecté en une minute

  1. Créez un jetonPage API & MCP de DumpCat, New token. Les jetons sont en lecture seule par défaut ; choisissez Full pour que l’assistant puisse lancer des sauvegardes.
  2. Copiez la configurationLa page insère l’adresse de votre serveur et le jeton dans la commande Claude Code, la configuration Claude Desktop et celle des autres clients.
  3. Testez, puis demandezTest MCP connection affiche le compte, l’accès et les outils dont l’assistant disposera.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

Mettez votre adresse et votre jeton, ou copiez la commande déjà remplie depuis la page API & MCP. Pour partager le serveur dans un projet sans le jeton, cette page propose aussi un .mcp.json qui lit le jeton dans l’environnement.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Ouvrez Settings → Developer → Edit Config, collez, puis redémarrez Claude Desktop. dumpcat mcp est une petite passerelle stdio qui tourne sur l’ordinateur où se trouve Claude Desktop ; sous Linux, command est le chemin du binaire dumpcat, et sous macOS vous le compilez avec Go.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }
  }
}

L’endpoint /api/mcp (streamable HTTP) fait partie de DumpCat, rien d’autre à installer. Les clients qui ne savent lancer qu’une commande locale utilisent dumpcat mcp, avec DUMPCAT_MCP_URL et DUMPCAT_MCP_TOKEN dans l’environnement.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md est toute la référence d’API en Markdown, rédigée par le serveur lui-même, donc toujours conforme à la version que vous utilisez : authentification, conventions, exemples curl et chaque route avec l’accès requis. Laissez un agent la lire et appeler l’API REST, ou collez-la dans un chat (API & MCP → Copy Markdown). /api/mcp/tools liste les outils MCP en JSON.

Vous avez perdu la machine qui fait tourner DumpCat ? Installez une nouvelle copie, rajoutez le stockage et cliquez sur Import backup catalog : toutes les sauvegardes réapparaissent. Même sans DumpCat, vous pouvez restaurer avec age, zstd et mysql ou pg_restore.

Connectivité

Base sans port ouvert ? Sauvegardée quand même.

Quand le serveur de sauvegarde ne peut pas joindre la base directement, à cause d’un pare-feu, d’un NAT ou d’une base qui n’écoute que sur 127.0.0.1, c’est le serveur de base de données qui se connecte à DumpCat. Il y a deux façons de faire, et aucune n’ouvre de port sur ce serveur. Sauvegardes, restaurations et restauration à un instant précis fonctionnent comme avec une connexion directe.

Agent HTTPS

Requis côté base de données
HTTPS sortant vers DumpCat
Base de données
Inchangée, même si elle n’écoute que sur 127.0.0.1
Installation
sudo ./install.sh --agent --server … --key …
Idéal pour
Ne toucher ni au réseau ni à la configuration MySQL

WireGuard intégré UDP · désactivé par défaut

Requis côté base de données
WireGuard standard, UDP 51820 sortant vers DumpCat
Base de données
Écoute sur l’adresse VPN, l’utilisateur autorise 10.66.0.1
Installation
Activez-le sur la page WireGuard, copiez dumpcat.conf, puis systemctl enable --now wg-quick@dumpcat
Idéal pour
Les équipes qui utilisent déjà WireGuard, ou une passerelle vers tout un réseau de bases

Le serveur de base de données ouvre la connexion ; les données circulent dans les deux sens à l’intérieur. Les sauvegardes physiques (XtraBackup / MariaBackup) passent par un agent lancé avec --allow-physical ; via WireGuard, elles exigent toujours que DumpCat soit installé sur le serveur de base de données.

Exploitation

Tout ce que vous auriez dû scripter vous-même

Tout est inclus dans DumpCat, et s’active et se règle depuis l’interface web.

Chiffré avant l’envoi
age (ChaCha20-Poly1305 + scrypt) tourne sur votre serveur : le fournisseur cloud ne peut pas lire vos données.
Contrôles d’intégrité
SHA-256 pour chaque fichier. La vérification relit, déchiffre, décompresse et cherche la ligne Dump completed.
Rétention GFS
Gardez N sauvegardes, N jours, la dernière de chaque jour, semaine et mois. Une chaîne incrémentale n’est supprimée qu’avec sa sauvegarde complète.
Restaurations prudentes
Chaque fichier passe un test de déchiffrement avant la suppression de la moindre base. Restaurez sous de nouveaux noms, ou sur un autre serveur et une autre version (MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
Comptes et rôles
admin, operator, viewer. Double authentification TOTP, jetons d’API, journal d’audit et verrouillage après des échecs de connexion répétés.
Notifications
E-mail, Telegram, Slack, Discord et webhooks signés HMAC, en cas d’échec ou de succès.
Bases derrière un pare-feu
Un agent sur le serveur de base de données se connecte à DumpCat en HTTPS, ou le serveur rejoint le WireGuard intégré. Aucun port à ouvrir vers la base.
Mise à jour intégrée
dumpcat update vérifie le SHA-256, sauvegarde la configuration, attend la fin des sauvegardes en cours et revient en arrière en cas d’échec.

Open source

Gratuit, open source, et vos données restent les vôtres

DumpCat est publié sous licence Apache-2.0. Ni compte, ni clé de licence, ni édition payante qui garderait des fonctionnalités pour elle : tout ce que présente cette page se trouve dans la version que vous téléchargez.

Licence Apache-2.0
Utilisez-le à la maison ou au travail, modifiez-le et redistribuez-le. Le texte complet se trouve dans LICENSE.
Aucune télémétrie
DumpCat n’envoie aucune donnée d’utilisation, nulle part. Le seul appel qu’il passe de lui-même consiste à lire latest.json une fois par jour pour annoncer les nouvelles versions, et vous pouvez le désactiver dans les paramètres (Settings).
Aucun intermédiaire
Sauvegardes, mots de passe des bases et clés de chiffrement ne transitent que de votre serveur vers le stockage de votre choix.
Versions signées
Chaque mise à jour est signée avec ed25519 et vérifiée par SHA-256 avant d’être installée. Pour compiler vous-même, il suffit de Go.

Compiler depuis les sources

bash
git clone https://github.com/theweakestharrison/DumpCat.git
cd DumpCat
go build -o dumpcat ./cmd/dumpcat
