Código abierto · Copias de seguridad y restauración para MySQL, MariaDB, PostgreSQL y SQL Server

Copias de seguridad sin bloquear la base de datos. Recuperación al segundo exacto.

DumpCat es un solo binario con interfaz web. Programa las copias de seguridad, las comprime y las cifra, envía copias a S3, Google Drive, OneDrive o SFTP, las verifica y recupera tus datos cuando los necesitas. Funciona en Linux y Windows, totalmente sin conexión a internet.

Instalación

Funcionando en un minuto

Un comando en Linux; en Windows, descargar y hacer doble clic. El instalador configura un servicio que arranca con la máquina y las herramientas de copia que corresponden a la versión de tu base de datos; la interfaz web va integrada en un solo archivo.

En el servidor Linux, pega este comando y presiona Enter:

bash
curl -fsSL https://dumpcat.cc/install.sh | sudo sh

Descarga la última versión, comprueba su suma de verificación y la instala en /opt/dumpcat como servicio systemd, con rclone, el cliente de MySQL/MariaDB, el mariabackup o XtraBackup correspondiente y mydumper cuando los repositorios lo incluyen; --postgres 16 agrega las herramientas cliente de PostgreSQL 16. Las opciones van después de sh -s --: --port 9090, --listen 127.0.0.1, --tls-auto.

  1. Descarga el .zip Descargar para Windows 1.8.0
  2. Descomprímelo: haz clic derecho en el archivo y elige Extract All.
  3. Haz doble clic en Install DumpCat y responde Yes. El navegador abre DumpCat; la ventana de instalación muestra el token de configuración.

Windows 10 / 11 o Windows Server 2016+ de 64 bits; se ejecuta como servicio de Windows. ¿Prefieres PowerShell? Ejecuta irm https://dumpcat.cc/install.ps1 | iex en PowerShell (como administrador). mydumper y XtraBackup para MySQL no están disponibles; usa DumpCat en Linux para bases de datos de cientos de GB.

¿Poca experiencia con la línea de comandos? Sigue la guía paso a paso (en inglés), con soluciones a los problemas habituales.

Pensado para IA · MCP

Deja que un asistente de IA configure y vigile tus copias, sin darle las llaves

DumpCat es un servidor MCP. Conecta Claude Code, Claude Desktop o cualquier otro cliente MCP con un token de API y pide las cosas con tus propias palabras: el asistente agrega servidores y almacenamientos, crea trabajos y simulacros de restauración, averigua qué falló o va con retraso, lee el registro y te explica por qué. Las contraseñas y claves las introduces tú en la interfaz web. Otros agentes de IA leen la referencia de la API en Markdown que tu propio servidor escribe para ellos.

Qué puede hacer un asistente

  • MirarToken de solo lectura, el predeterminadoResumen y alertas, trabajos, copias, errores y registros, archivado de binlog / WAL, resultados de restauraciones y simulacros, vistas previas de recuperación a un punto en el tiempo.
  • LanzarToken de acceso completo, operator o adminEjecutar una copia, verificar una copia, iniciar un simulacro de restauración. El cliente de IA te pregunta antes de cada una.
  • ConfigurarToken ManageAgregar servidores y almacenamientos, crear y cambiar trabajos y simulacros de restauración. Las contraseñas, claves y frases de paso nunca pasan por el asistente: te da un enlace para que las introduzcas tú.
  • Nunca por MCPCon ningún tokenRestauraciones, borrados y los ajustes de DumpCat. Ninguna opción los activa: se hacen solo en la interfaz web.

Las respuestas nunca contienen contraseñas, claves ni tokens, y ninguna herramienta los acepta; las credenciales que aparecen en errores y registros se ocultan. Cada llamada pasa por la API REST con tu token, así que se comprueba como cualquier otra petición y queda en el registro de auditoría.

Conéctalo en un minuto

  1. Crea un tokenPágina API & MCP de DumpCat, New token: Read-only (el predeterminado) solo mira, Full también lanza copias, Manage también las configura.
  2. Copia la configuraciónLa página rellena la dirección de tu servidor y el token en el comando de Claude Code, la configuración de Claude Desktop y la de otros clientes.
  3. Prueba y preguntaTest MCP connection muestra la cuenta, el acceso y las herramientas que recibirá el asistente.
bash
claude mcp add --transport http dumpcat \
  https://backup.example.com/api/mcp \
  --header "Authorization: Bearer mv_…"

Pon tu propia dirección y tu token, o copia el comando ya rellenado de la página API & MCP. Para compartir el servidor en un proyecto sin el token, esa página también ofrece un .mcp.json que lee el token del entorno.

claude_desktop_config.json
{
  "mcpServers": {
    "dumpcat": {
      "command": "C:\\Program Files\\DumpCat\\dumpcat.exe",
      "args": ["mcp"],
      "env": {
        "DUMPCAT_MCP_URL": "https://backup.example.com",
        "DUMPCAT_MCP_TOKEN": "mv_…"
      }
    }
  }
}

Abre Settings → Developer → Edit Config, pega y reinicia Claude Desktop. dumpcat mcp es un pequeño puente stdio que se ejecuta en el equipo donde está Claude Desktop; en Linux, command es la ruta del binario dumpcat, y en macOS lo compilas con Go.

json
{
  "mcpServers": {
    "dumpcat": {
      "url": "https://backup.example.com/api/mcp",
      "headers": { "Authorization": "Bearer mv_…" }
    }
  }
}

El endpoint /api/mcp (streamable HTTP) forma parte de DumpCat, no hay nada más que instalar. Los clientes que solo inician un comando local usan dumpcat mcp, con DUMPCAT_MCP_URL y DUMPCAT_MCP_TOKEN en el entorno.

bash
curl -H "Authorization: Bearer $TOKEN" \
  https://backup.example.com/api/docs.md

/api/docs.md es toda la referencia de la API en Markdown, escrita por el propio servidor, así que siempre coincide con la versión que ejecutas: autenticación, convenciones, ejemplos con curl y cada ruta con el acceso que necesita. Deja que un agente la lea y llame a la API REST, o pégala en un chat (API & MCP → Copy Markdown). /api/mcp/tools lista las herramientas MCP en JSON.

Métodos de copia

La herramienta adecuada para cada base de datos y tamaño

Para MySQL y MariaDB, DumpCat utiliza mysqldump, mydumper y XtraBackup / MariaBackup. Al agregar un servidor, Test connection muestra la versión, el datadir, el tamaño de cada base de datos y qué métodos funcionan en esa máquina.

PostgreSQL 10 y posteriores: pg_dump por base de datos, con volcado y restauración de tablas en paralelo, con otro nombre o en otro servidor; pg_basebackup para todo el clúster a través de una conexión de replicación, con archivado continuo de WAL para recuperar hasta un momento, un punto de restauración o una posición del WAL.

SQL Server 2012 y posteriores, en Windows, Linux y contenedores: copias nativas completas y diferenciales con BACKUP DATABASE (sin herramientas cliente), restauración con otro nombre o en otro servidor, simulacros de restauración con DBCC CHECKDB y copias programadas del log de transacciones para recuperar hasta un momento, una transacción marcada o un LSN. SQL Server escribe sus copias en su propio servidor: DumpCat las lee de una carpeta compartida, o un agente en ese servidor las transfiere sin compartir nada.

Conectividad

¿Base de datos sin puertos abiertos? También tiene copia de seguridad.

Cuando el servidor de copias de seguridad no puede conectarse directamente a la base de datos, por un firewall, NAT o una base de datos que solo escucha en 127.0.0.1, deja que sea el servidor de base de datos el que se conecte a DumpCat. Hay dos maneras, y ninguna abre un puerto en el servidor de base de datos. Las copias de seguridad, las restauraciones y la recuperación a un punto en el tiempo funcionan igual que con una conexión directa.

Agente HTTPS

El servidor de base de datos necesita
HTTPS saliente hacia DumpCat
Base de datos
Sin cambios, aunque solo escuche en 127.0.0.1
Instalación
sudo ./install.sh --agent --server … --key …
Ideal para
No tocar la red ni la configuración de MySQL

WireGuard integrado UDP · desactivado por defecto

El servidor de base de datos necesita
WireGuard estándar, UDP 51820 saliente hacia DumpCat
Base de datos
Escucha en la dirección de la VPN y el usuario acepta conexiones desde 10.66.0.1
Instalación
Actívalo en la página de WireGuard, copia dumpcat.conf, systemctl enable --now wg-quick@dumpcat
Ideal para
Equipos que ya usan WireGuard, o como puerta de enlace a toda una red de bases de datos

El servidor de base de datos abre la conexión; los datos circulan en ambos sentidos dentro de ella. Las copias físicas (XtraBackup / MariaBackup) funcionan a través de un agente iniciado con --allow-physical; con WireGuard siguen necesitando DumpCat instalado en el servidor de base de datos. Los archivos de copia de SQL Server también pasan por un agente iniciado con --allow-mssql-dir, sin carpeta compartida.

Operaciones

Lo que de otro modo tendrías que programar tú mismo

Todo viene incluido en DumpCat y se activa y ajusta desde la interfaz web.

Cifrado antes de subir
age (ChaCha20-Poly1305 + scrypt) se ejecuta en tu servidor, así que el proveedor de la nube no puede leer tus datos.
Comprobación de integridad
SHA-256 para cada archivo. La verificación vuelve a leer, descifra, descomprime y busca la línea Dump completed.
Retención GFS
Conserva N copias, N días, la última de cada día, semana y mes. Las cadenas incrementales solo se eliminan junto con su copia completa.
Restauraciones cuidadosas
Se comprueba que cada archivo se puede descifrar antes de eliminar cualquier base de datos. Restaura con otros nombres, o en otro servidor y otra versión (MySQL 8 ↔ MariaDB, PostgreSQL 15 → 16).
Cuentas y roles
admin, operator, viewer. Doble factor TOTP, tokens de API, un registro de auditoría y bloqueo tras varios inicios de sesión fallidos.
Notificaciones
Correo electrónico, Telegram, Slack, Discord y webhooks firmados con HMAC, en caso de fallo o de éxito.
Bases de datos tras un firewall
Un agente en el servidor de base de datos se conecta a DumpCat por HTTPS, o el servidor se une al WireGuard integrado. No hace falta abrir ningún puerto hacia la base de datos.
Autoactualización
dumpcat update comprueba el SHA-256, hace una copia de la configuración, espera a que terminen las copias en curso y revierte los cambios si algo falla.

Sin telemetría
DumpCat no envía datos de uso a ningún sitio. La única llamada que hace por su cuenta es leer latest.json una vez al día para avisar de nuevas versiones, y puedes desactivarla en Settings.
Sin intermediarios
Las copias de seguridad, las contraseñas de las bases de datos y las claves de cifrado solo viajan de tu servidor al almacenamiento que elijas.
Versiones firmadas
Cada actualización se firma con ed25519 y se comprueba con SHA-256 antes de instalarse. Para compilarlo tú mismo solo necesitas Go.
