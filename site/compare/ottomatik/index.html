DumpCat vs Ottomatik

Ottomatik is a hosted service that logs in to your server over SSH to run and upload backups. DumpCat is a free, open-source backup manager that runs on the server itself. Here is how they compare for MySQL and MariaDB.

How it runsSelf-hosted: one binary with a web UI, running as a systemd or Windows service next to your database.Hosted SaaS. Its servers connect to yours over SSH and install Python, pip and the AWS CLI there. A help article also describes remote MySQL backups that run on Ottomatik's own servers, without SSH access to yours.
PlatformsLinux (amd64, arm64) and Windows (64-bit).Linux servers over SSH (FreeBSD with a manual install). Remote MySQL backups only need the database credentials and an allowlisted IP.
DatabasesMySQL 5.7, 8.0, 8.4, Percona Server, MariaDB 10.x and 11.x; PostgreSQL 10 and newer; Microsoft SQL Server 2012 and newer (Windows, Linux, containers).MySQL, PostgreSQL and MongoDB. MariaDB support is not stated on the pages we checked.

PostgreSQL: pg_dump (tables in parallel) and pg_basebackup (the whole cluster). SQL Server: native full and differential backups (BACKUP DATABASE, no client tools).mysqldump, with options for a single transaction or skipping locks, routines and events.
Point-in-time recoveryYes. Continuous binlog archiving; restore to a timestamp, a binlog position or just before a GTID. PostgreSQL: continuous WAL archiving; restore to a timestamp, a restore point or a WAL position. SQL Server: scheduled log backups; restore to a timestamp, a marked transaction or an LSN.Partial: binlogs can be uploaded to S3 or copied by a file backup job; replaying them is manual.
StorageLocal disk / NFS, S3 and compatibles, Google Drive, OneDrive, SFTP, FTP / FTPS, WebDAV, Backblaze B2, Azure Blob, Dropbox and every rclone backend; several per job.Ottomatik's storage, Amazon S3 and S3-compatible, Google Drive, Dropbox, Backblaze.
Encryptionage encryption on your server before anything is uploaded; zstd compression; SHA-256 for every file.Credentials are stored encrypted; encryption of the backup files is not described on the pages we checked.

Choose Ottomatik if

  • You want scheduling and monitoring that run outside your server, with nothing to keep updated yourself.
  • You back up PostgreSQL and MongoDB too and want one dashboard for all of them.
  • You want backups as often as every minute and one-click restores to another server.

Choose DumpCat if

  • You would rather not give a third party SSH access to your database server.
  • You want point-in-time recovery from the UI instead of replaying binlogs by hand.
  • You run Windows servers, or need hot physical backups for large databases.
  • You want it free, with no limits on jobs or storage.

Switching from Ottomatik

  1. Install DumpCat on the database server.
  2. Add your S3, Google Drive or Dropbox storage to DumpCat, in a new folder.
  3. Recreate each job with its schedule and retention, turn on binlog archiving, and run it once.
  4. Once DumpCat's retention covers what you need, remove Ottomatik's SSH key from the server.
