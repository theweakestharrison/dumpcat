DumpCat vs SQLBackupAndFTP

SQLBackupAndFTP của Pranas.NET là ứng dụng Windows lâu năm, backup SQL Server, MySQL, MariaDB và PostgreSQL ra ổ local và cloud. DumpCat là công cụ quản lý backup MySQL, MariaDB, PostgreSQL và SQL Server miễn phí, mã nguồn mở, chạy trên Linux và Windows. Dưới đây là khác biệt giữa hai bên.

Chi tiết từng mục

DumpCatSQLBackupAndFTP
Giá và giấy phépMiễn phí, mã nguồn mở (Apache-2.0). Không cần tài khoản hay license key.Mua một lần, theo từng máy: Free (2 database), Lite $39 (5 database), Standard $89, Professional $129, Professional Lifetime $499. Có thêm gói dịch vụ hằng năm tùy chọn.
Cách chạyTự host: một file chạy kèm giao diện web, chạy như service systemd hoặc Windows service cạnh database.Ứng dụng desktop kèm Windows service; cần .NET Framework 4.7.2. Với Linux, hãng có sản phẩm riêng là SqlBak.
Hệ điều hànhLinux (amd64, arm64) và Windows (64-bit).Chỉ Windows. Backup full vẫn kết nối được tới MySQL trên máy khác qua TCP/IP hoặc SSH tunnel; backup incremental thì cần cài ứng dụng trên chính server MySQL.
DatabaseMySQL 5.7, 8.0, 8.4, Percona Server, MariaDB 10.x và 11.x; PostgreSQL 10 trở lên; Microsoft SQL Server 2012 trở lên (Windows, Linux, container).MySQL 5.6, 5.7, 8.0 và 8.4, MariaDB 10.6, 10.11 và 11.4; ngoài ra SQL Server và PostgreSQL.
Phương thức backupLogical bằng mysqldump / mariadb-dump hoặc mydumper song song; backup vật lý nóng bằng XtraBackup / MariaBackup, có incremental. Không khóa InnoDB. PostgreSQL: pg_dump (các bảng song song) và pg_basebackup (cả cluster). SQL Server: backup full và differential gốc (BACKUP DATABASE, không cần client).Bản full là script SQL từ mysqldump. Incremental (từ Standard) chép binlog sau FLUSH BINARY LOGS và cần cài ứng dụng ngay trên server MySQL. Không có backup vật lý.
Khôi phục theo thời điểmCó. Lưu binlog liên tục; khôi phục đến một thời điểm, một vị trí binlog hoặc ngay trước một GTID. PostgreSQL: lưu WAL liên tục; khôi phục đến một thời điểm, một restore point hoặc một vị trí WAL. SQL Server: log backup theo lịch; khôi phục đến một thời điểm, một marked transaction hoặc một LSN.Một phần: incremental là binlog, nhưng không có tài liệu về khôi phục đến một thời điểm chọn trước.
Nơi lưu trữỔ local / NFS, S3 và tương thích, Google Drive, OneDrive, SFTP, FTP / FTPS, WebDAV, Backblaze B2, Azure Blob, Dropbox và mọi backend của rclone; nhiều nơi cho một job.Local / NAS, FTP, SFTP, FTPS, OneDrive, Box, Backblaze B2, Yandex, Google Drive và Dropbox. Amazon S3, tương thích S3, Azure và OneDrive for Business cần gói Professional. Một job có thể gửi mỗi bản backup tới nhiều nơi lưu, mỗi nơi có thời hạn lưu giữ riêng (kể cả GFS).
Mã hóaMã hóa age ngay trên server trước khi upload; nén zstd; SHA-256 cho từng file.Nén zip hoặc 7z; mã hóa AES-256 bằng mật khẩu chỉ có ở Professional.
Lịch và retentionLịch kiểu cron; retention riêng cho từng nơi lưu theo số bản, số ngày hoặc GFS (ngày / tuần / tháng).Có bộ lập lịch và tự dọn backup cũ.
Khôi phụcNgay trên giao diện web: restore sang tên database mới, thử giải mã mọi file trước khi xóa gì, kiểm tra toàn vẹn sau mỗi lần chạy.Khôi phục một cú nhấp cả chuỗi full + incremental, sang tên mới hoặc server khác. Job khôi phục cũng chạy được theo lịch, có thông báo khi thành công hoặc thất bại.
Dữ liệu đi đâuĐi thẳng từ server của bạn tới nơi lưu bạn chọn, không qua bên thứ ba nào.Từ máy Windows của bạn tới storage của bạn.
Thông báoEmail, Telegram, Slack, Discord và webhook ký HMAC.Email ở mọi phiên bản; Slack, Teams, Discord và webhook từ gói Lite.

Chọn SQLBackupAndFTP nếu

  • Bạn thích mua bản quyền một lần và dùng ứng dụng desktop có wizard hướng dẫn cài storage cloud.
  • Bạn muốn được hãng hỗ trợ qua gói dịch vụ trả phí.

Chọn DumpCat nếu

  • Server MySQL, MariaDB của bạn chạy Linux: DumpCat chạy trực tiếp trên Linux (amd64, arm64) lẫn Windows.
  • Bạn cần khôi phục theo thời điểm thực sự: lưu binlog liên tục và khôi phục đến từng giây hoặc ngay trước một GTID.
  • Database của bạn lớn: mydumper song song và backup vật lý nóng bằng XtraBackup / MariaBackup.
  • Bạn muốn S3, mã hóa và mọi kênh thông báo mà không phải mua gói cao: DumpCat miễn phí và mã nguồn mở.

Chuyển từ SQLBackupAndFTP sang DumpCat

  1. Cài DumpCat trên server database (Linux hoặc Windows).
  2. Thêm storage đang dùng (Google Drive, S3, SFTP…) vào DumpCat, trong một thư mục mới.
  3. Tạo lại từng job, và bật lưu binlog ở những chỗ bạn đang dùng incremental của SQLBackupAndFTP.
  4. Chạy thử từng job và xem kết quả kiểm tra toàn vẹn; giữ backup cũ cho tới khi retention của DumpCat phủ được cùng khoảng thời gian.

So sánh khác

  • DumpCat vs SimpleBackupsDịch vụ trực tuyến backup server, database và storage, từ gói miễn phí đến $299/tháng.
  • DumpCat vs PortabaseDashboard backup mã nguồn mở dùng agent cho 11 nguồn dữ liệu; với MySQL chỉ backup logical (mysqldump).
  • DumpCat vs DatabasusỨng dụng web backup nhiều loại database, mã nguồn mở (trước là Postgresus); với MySQL chỉ backup logical.
  • DumpCat vs SqlBakDịch vụ backup dùng agent, của nhà làm SQLBackupAndFTP, tính phí theo server.
  • DumpCat vs AutoMySQLBackupScript cron kinh điển, xoay vòng theo ngày / tuần / tháng; dự án gốc dừng từ 2011.
  • DumpCat vs Percona XtraBackupEngine backup vật lý nóng mã nguồn mở. DumpCat chạy nó giúp bạn, kèm lịch, nơi lưu và khôi phục.
  • DumpCat vs MySQL Enterprise BackupCông cụ backup vật lý thương mại của Oracle, nằm trong MySQL Enterprise Edition.
  • DumpCat vs SnapShooterDịch vụ backup thuộc DigitalOcean; lần cập nhật sản phẩm gần nhất được liệt kê là tháng 9/2024.
  • DumpCat vs NavicatPhần mềm quản trị database trả phí phổ biến; backup là tính năng phụ, lưu local, chạy theo lịch.
  • DumpCat vs OttomatikDịch vụ lên lịch chạy mysqldump trên server của bạn qua SSH, từ $14/tháng.
  • DumpCat vs BackupSheepTừng là SaaS, nay là bản beta mã nguồn mở tự host cho database, snapshot cloud và WordPress.
